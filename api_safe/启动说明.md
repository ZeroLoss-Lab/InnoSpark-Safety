# 增强版拦截器启动说明

## 快速启动

### 方式一：完整系统启动（推荐）
自动启动前后拦截BERT API + 主API服务，使用远程拦截模式：

```bash
python start_complete_system.py
```

这个脚本会按顺序启动：
1. 前拦截BERT API服务 (端口8001)
2. 后拦截BERT API服务 (端口8002)  
3. 主API服务 (端口8003) - 使用远程拦截模式

### 方式二：分步启动

#### 第1步：启动前后拦截BERT API服务
```bash
cd safe_api
python start_services.py
```

#### 第2步：启动主API服务（远程拦截模式）
```bash
python start_server.py --remote-intercept --port 8003
```

### 方式三：本地集成模式启动
仅启动主API服务，使用本地集成的拦截器：

```bash
python start_server.py
```

### 方式四：超简单启动
```bash
python quick_start.py
```

## 启动参数说明

### start_server.py 参数
```bash
python start_server.py [选项]

选项:
  -p, --port PORT              API服务端口 (默认: 8001)
  -v, --vllm URL              vLLM服务地址 (默认: http://localhost:8000)
  -r, --rag URL               RAG服务地址 (默认: http://localhost:8000/retrieve)
  -k, --api-key KEY           API密钥 (默认: your_api_key_here)
  --host HOST                 服务绑定地址 (默认: 0.0.0.0)
  --no-rag                    禁用RAG系统
  --no-front                  禁用前拦截
  --no-post                   禁用后拦截
  --remote-intercept          使用远程拦截模式
  --front-intercept-url URL   前拦截API地址
  --post-intercept-url URL    后拦截API地址
  --check-only                仅检查环境
```

### 示例命令

#### 使用远程拦截模式启动
```bash
python start_server.py --remote-intercept --port 8003
```

#### 禁用RAG功能启动
```bash
python start_server.py --no-rag
```

#### 自定义端口和API密钥
```bash
python start_server.py --port 8002 --api-key "my_secret_key"
```

#### 仅检查环境不启动
```bash
python start_server.py --check-only
```

## 服务端口说明

| 服务 | 默认端口 | 说明 |
|------|----------|------|
| 前拦截BERT API | 8001 | 高敏词+双阈值BERT前拦截 |
| 后拦截BERT API | 8002 | BERT后拦截 |
| 主API服务 | 8001/8003 | OpenAI兼容的主API服务 |
| vLLM服务 | 8000 | 大语言模型服务 |
| RAG服务 | 8000/retrieve | 检索增强生成服务 |

## 拦截模式对比

### 本地集成模式
- **优点**: 性能更好，延迟更低，部署简单
- **缺点**: 需要本地加载BERT模型，内存占用大
- **适用**: 单机部署，性能要求高的场景

### 远程拦截模式  
- **优点**: 服务解耦，可独立扩展，内存占用小
- **缺点**: 网络延迟，需要额外的API服务
- **适用**: 分布式部署，需要独立扩展拦截服务的场景

## 故障排除

### 1. 服务启动失败
- 检查端口是否被占用：`netstat -an | grep 8001`
- 检查依赖是否安装：`pip install -r requirements.txt`
- 查看日志文件：`tail -f logs/api.log`

### 2. 拦截不生效
- 确认拦截器已启用：查看启动日志
- 检查关键词文件：确保数据文件存在
- 验证BERT模型：确保模型文件完整

### 3. RAG服务连接失败
- 检查RAG服务是否启动：`curl http://localhost:8000/retrieve`
- 验证网络连接：`ping localhost`
- 查看RAG服务日志

### 4. vLLM服务连接失败
- 检查vLLM服务：`curl http://localhost:8000/v1/models`
- 确认服务地址：检查VLLM_API_BASE配置

## 配置文件

### 环境变量配置
可以创建 `.env` 文件：

```bash
# 服务配置
VLLM_API_BASE=http://localhost:8000
HOST=0.0.0.0
PORT=8001
API_KEY=your_api_key_here

# 拦截器配置
ENABLE_FRONT_INTERCEPT=true
ENABLE_POST_INTERCEPT=true
USE_LOCAL_INTERCEPT=false

# 远程拦截API地址
FRONT_INTERCEPT_URL=http://localhost:8001/intercept
POST_INTERCEPT_URL=http://localhost:8002/intercept

# RAG配置
ENABLE_RAG=true
RAG_SERVICE_URL=http://localhost:8000/retrieve
RAG_TOP_K=5

# BERT阈值配置
BERT_FRONT_HIGH_THRESHOLD=0.97
BERT_FRONT_LOW_THRESHOLD=0.00002
BERT_POST_THRESHOLD=0.5
```

## 性能优化建议

1. **使用远程拦截模式**：适合生产环境，便于扩展
2. **合理设置worker数量**：根据CPU核心数调整
3. **优化BERT阈值**：根据业务需求调整敏感度
4. **启用连接池**：减少网络开销
5. **配置日志级别**：生产环境使用INFO或WARNING级别
