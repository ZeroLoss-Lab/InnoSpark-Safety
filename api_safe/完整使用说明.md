# 主API服务完整使用说明

## 📖 概述

`start_main_api.py` 是主API服务启动脚本，专门用于连接到你独立运行的外部服务：
- Safe API服务（前后拦截BERT）
- RAG服务  
- vLLM服务

**主启动脚本完全控制所有功能开关、阈值配置和服务地址**

## 🚀 快速开始

### 基本启动
```bash
python start_main_api.py
```

默认配置：
- 主API端口：8003
- 前拦截地址：http://localhost:8001/intercept
- 后拦截地址：http://localhost:8002/intercept
- RAG服务地址：http://localhost:8000/retrieve
- vLLM服务地址：http://localhost:8000
- 启用前拦截、后拦截、RAG功能
- 禁用API文档访问

## 📋 完整参数列表

### 基本服务配置
```bash
--host HOST                    # 服务绑定地址，默认: 0.0.0.0
--port PORT                    # 主API服务端口，默认: 8003
--vllm URL                     # vLLM服务地址，默认: http://localhost:8000
```

### 外部服务地址配置
```bash
--front-url URL                # 前拦截API地址，默认: http://localhost:8001/intercept
--post-url URL                 # 后拦截API地址，默认: http://localhost:8002/intercept
--rag-url URL                  # RAG服务地址，默认: http://localhost:8000/retrieve
```

### 功能开关控制
```bash
--no-front                     # 禁用前拦截功能
--no-post                      # 禁用后拦截功能
--no-rag                       # 禁用RAG功能
--enable-docs                  # 启用API文档访问（默认禁用）
```

### BERT阈值配置
```bash
--bert-front-high FLOAT        # BERT前拦截高阈值，默认: 0.97
--bert-front-low FLOAT         # BERT前拦截低阈值，默认: 0.00002
--bert-post FLOAT              # BERT后拦截阈值，默认: 0.5
```

### RAG功能配置
```bash
--rag-top-k INT                # RAG检索top-k数量，默认: 5
--rag-timeout FLOAT            # RAG服务超时时间（秒），默认: 10.0
```

### API密钥配置
```bash
--api-keys FILE                # API密钥JSON文件路径，默认: api_keys.json
--single-key KEY               # 使用单个API密钥（向后兼容）
```

### 超时配置
```bash
--intercept-timeout FLOAT      # 拦截服务超时时间（秒），默认: 10.0
```

## 🔧 阈值配置详解

### BERT前拦截双阈值机制
- **高阈值** (`--bert-front-high`): 有害性 ≥ 此值时直接拦截
- **低阈值** (`--bert-front-low`): 有害性 > 此值但 < 高阈值时进入中间判断
- **中间判断流程**: 检查次高敏关键词 → 调用RAG系统

### BERT后拦截阈值
- **后拦截阈值** (`--bert-post`): 有害性 ≥ 此值时拦截输出

### 推荐阈值配置

#### 严格模式（高安全）
```bash
--bert-front-high 0.99 --bert-front-low 0.00001 --bert-post 0.3
```

#### 平衡模式（默认）
```bash
--bert-front-high 0.97 --bert-front-low 0.00002 --bert-post 0.5
```

#### 宽松模式（高性能）
```bash
--bert-front-high 0.95 --bert-front-low 0.0001 --bert-post 0.7
```

## 🛠️ 故障排除

### 1. 服务启动失败
```bash
# 检查端口占用
netstat -an | grep 8003

# 检查API密钥文件
python -c "import json; print(json.load(open('api_keys.json')))"

# 检查依赖
pip list | grep -E "(fastapi|uvicorn|requests)"
```

### 2. 外部服务连接失败
```bash
# 测试各个外部服务
curl -v http://localhost:8001/health
curl -v http://localhost:8002/health
curl -v http://localhost:8000/v1/models
curl -v -X POST http://localhost:8000/retrieve \
  -H "Content-Type: application/json" \
  -d '{"query":"test","top_k":1}'
```

### 3. 拦截功能不生效
- 确认Safe API服务已启动并可访问
- 检查拦截开关是否正确设置
- 验证阈值配置是否合理
- 查看主API日志输出

### 4. RAG功能异常
- 确认RAG服务已启动并可访问
- 检查RAG服务地址配置
- 验证RAG超时设置
- 测试RAG服务独立调用

### 5. API密钥问题
- 检查密钥文件格式是否正确
- 确认密钥的`enabled`字段为`true`
- 验证HTTP请求头格式：`Authorization: Bearer your-key`

2. **使用HTTPS**: 在反向代理中配置SSL

## 关键词文件路径配置

### 配置参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|-------|------|
| `--high-sensitive-path` | string | ./safe_api/data/high_sensitive_keywords.json | 高敏感关键词文件路径 |
| `--low-sensitive-path` | string | ./safe_api/data/high_sensitive_keywords-2.json | 低敏感关键词文件路径 |

### 使用示例

#### 自定义关键词文件路径
```bash
python start_main_api.py \
  --high-sensitive-path /path/to/custom/high_sensitive.json \
  --low-sensitive-path /path/to/custom/low_sensitive.json
```

#### 使用相对路径
```bash
python start_main_api.py \
  --high-sensitive-path ./data/my_high_sensitive.json \
  --low-sensitive-path ./data/my_low_sensitive.json
```

### 文件格式说明

#### 高敏感关键词文件格式 (high_sensitive_keywords.json)
```json
[
  "placeholder_category_alpha",
  "placeholder_category_beta", 
  "种族歧视",
  "政治敏感"
]
```

#### 低敏感关键词文件格式 (high_sensitive_keywords-2.json)
```json
[
  "争议话题",
  "敏感讨论",
  "需要谨慎",
  "可能有风险"
]
```

### 注意事项

1. **文件路径**: 支持相对路径和绝对路径
2. **文件格式**: 必须是有效的JSON格式
3. **文件编码**: 建议使用UTF-8编码
4. **文件存在性**: 启动时会检查文件是否存在
5. **动态更新**: 修改文件后需要重启Safe API服务
